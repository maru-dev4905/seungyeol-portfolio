# D-006 섹션 순서: sort_order

- 상태: 일부 미정 (컬럼 이름은 확정, 드래그 정렬 방식은 미정)
- 날짜: 2026-11-17

> 순서 컬럼 이름은 `seq`에서 `sort_order`로 바꿨다. 드래그로 순서를 바꿀 때의 처리 방식은 아직 정하지 않았다.

## 배경

관리자에서 섹션을 드래그해 순서를 바꿀 수 있어야 한다.

## 이름 변경 (확정)

`seq`는 자동 증가 번호처럼 읽힌다. `projects.sort_order`와 이름을 맞춰 `sort_order`로 정했다.

## 문제

1, 2, 3, 4 중 4번을 맨 위로 옮기면 **4개 행이 전부 바뀐다.**
`UNIQUE(project_id, sort_order)`가 있으면 바꾸는 도중 번호가 잠깐 겹쳐 에러가 난다.

## 고민한 선택지 (미결정)

| 안 | 방식 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. 통째로 다시 매기기 | 프론트가 정렬된 id 목록을 보내고, Nest가 트랜잭션 안에서 전부 다시 매김. UNIQUE는 `DEFERRABLE`로 걸어 트랜잭션 끝에 검사 | 구현이 단순, 번호가 항상 깔끔 | 여러 행이 바뀜 |
| B. 사이값 넣기 | 1000, 2000, 3000처럼 띄우고, 사이로 옮기면 1500 같은 중간값 | 행 하나만 바뀜 | 간격이 좁아지면 다시 매겨야 함 |

## 결정

미정. **섹션 수가 적고 관리자가 한 명**이라는 조건을 놓고 고른다.
(이 조건이면 A가 단순해 보이지만, 같이 탐구해서 정한다.)

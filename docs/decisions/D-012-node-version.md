# D-012 Node 버전은 22 LTS로 고정한다

- 상태: 확정
- 날짜: 2026-11-17

> `.nvmrc`와 루트 `package.json`의 `engines`에 Node 22를 고정한다.

## 배경

모노레포 뼈대를 세팅하는 시점에 로컬 Node는 v24.14.0이었다.
Vercel 배포, Next, Nest가 같은 Node에서 도는 구조라 버전이 어긋나면 "내 컴퓨터에서만 되는" 문제가 생긴다.

## 고민한 선택지

| 안 | 방식 | 결과 |
| --- | --- | --- |
| **A. Node 22 LTS** | `.nvmrc`=22, `engines: ">=22 <23"` | **채택** |
| B. Node 24 | 로컬 버전과 동일 | Vercel 지원 버전과 라이브러리 호환을 직접 확인해야 해서 보류 |

## 결정

- `.nvmrc`: `22`
- 루트 `package.json`: `"engines": { "node": ">=22 <23" }`
- 앱의 `@types/node`도 `^22`로 맞춘다. (create-next-app은 `^20`, Nest는 `^24`를 깔았다.)

## 이유

- LTS라 안정적이고 Vercel이 기본으로 지원한다.
- 로컬, CI, 배포가 같은 메이저 버전을 쓰게 한다.

## 비용

로컬 기본이 v24라서 이 프로젝트에서는 `nvm use`(또는 `nvm install 22`)가 필요하다. `pnpm`이 `engines`를 어기면 경고한다.

## 면접 포인트

"런타임 버전을 왜 고정했나요?" → 로컬·CI·배포의 차이를 없애려고. 버전 선언을 한 곳(`.nvmrc`, `engines`)에 둔다.

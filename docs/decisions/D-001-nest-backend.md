# D-001 포트폴리오에 Nest 백엔드를 두고 관리자 기능을 만든다

- 상태: 확정
- 날짜: 2026-11-17

> 코드를 고치지 않고 프로젝트와 섹션을 추가하는 관리자 기능을 만들기 위해 NestJS 백엔드를 둔다.

## 배경

보통 포트폴리오는 Next 하나로 충분하다. 백엔드를 두면 **왜 두었는지 설명할 수 있어야** 한다.

## 고민한 선택지

| 안 | 방식 | 결과 |
| --- | --- | --- |
| A | Next만 쓰고 콘텐츠는 코드로 관리 | 프로젝트를 추가할 때마다 코드를 고쳐야 함 |
| B | Next + Nest + Supabase로 관리자 기능 제작 | **채택** |

## 결정

- Next.js + NestJS + Supabase(Postgres, Auth, Storage), 배포는 Vercel.
- 완성 후 기존 `seungyeol.kr` 도메인을 이 사이트로 교체한다.
- 1차 범위: 섹션 추가·삭제, 순서 변경, 저장 후 실제 페이지 확인. 로그인은 본인 1명(Supabase Auth).

## 이유

- 프로젝트를 추가할 때마다 코드를 고치는 반복 작업을 없앤다.
- NestJS는 Vercel에서 설정 없이 Function 하나로 배포된다. 서버를 따로 두지 않아도 된다.

## 면접 포인트

- WEAVE·MeerKit과 같은 메시지로 이어진다: **반복되는 일을 도구로 바꾼다.**

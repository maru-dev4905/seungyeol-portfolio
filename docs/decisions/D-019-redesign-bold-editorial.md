# D-019 리디자인: 시원한 에디토리얼 레이아웃 + 디더링 셰이더 + Lenis/GSAP 모션

- 상태: 일부 미정 (히어로 문구, 서체, 픽셀 숫자 서체는 계획 단계에서 확정)
- 날짜: 2026-11-18

> D-018의 어두운 바탕 + 셰이더 + 굴절 글래스는 유지하고, **레이아웃·팔레트·모션을 다시 잡는다.**
> 레퍼런스 #8(artify)과 #6(디더링 그라데이션)이 우선이고, #7(디지털 문자 조각)은 나중에 더하는 선택 요소다.
> 스크롤은 Lenis, 애니메이션은 GSAP(ScrollTrigger, SplitText)로 한다.

## 배경

D-017·D-018로 만든 상세 샘플을 보고 "너무 정적이고, 가독성은 좋지만 한국 관공서 같다"는 피드백을 받았다. 원인은 다음과 같다.

- 구조가 문서형이다: 좌측 목차, 박스 안의 박스, 균일한 여백, 작은 제목.
- 움직임이 배경 덩어리 하나뿐이고 스크롤·글자에는 반응이 없다.
- 팔레트가 청록 한 색이다. 레퍼런스는 검정 바탕에 주황·파랑·마젠타가 섞인다.
- 서체(Noto Sans KR 본문)가 공문서 인상을 더한다.

레퍼런스에서 읽은 것:

| 레퍼런스 | 가져올 것 |
| --- | --- |
| **#8** artify (우선) | 검정 바탕, 주황·파랑·빨강이 휘감는 큰 곡선 하나, 색 점이 섞인 그레인, 화면 중앙의 거대한 한 줄 제목과 짧은 문장, 글래스 알약 네비게이션, 흰 알약 버튼, 스크롤 표시 |
| **#6** 도트 그라데이션 (우선) | 그라데이션이 **디더링(도트 패턴)** 으로 찍힌 질감, 검은 카드, 큰 픽셀·모노 서체 숫자 |
| #7 (후순위) | 흰 바탕의 흐린 덩어리 위로 `[1,0]` 같은 모노스페이스 문자와 도트 조각이 움직이는 디지털 느낌. 말씀하신 나비 모양 문자 그림도 같은 계열 |

## 고민한 선택지

애니메이션 도구

| 안 | 방식 | 결과 |
| --- | --- | --- |
| **GSAP** | 명령형. ScrollTrigger(pin·scrub·snap), SplitText, 타임라인 | **채택.** 이 사이트의 핵심이 스크롤 연출이다 |
| Motion(구 Framer Motion) | React 선언형. 제스처, 스프링, 레이아웃·exit 애니메이션 | 상태 전환 UI에는 강하지만 스크롤 연출(고정·구간 제어)과 글자 분할이 약하다. 둘을 섞으면 설명할 것이 늘어서 하나만 쓴다. 관리자 정렬 UI(D-006)에서 다시 검토할 수 있다 |
| 직접 구현(CSS + IntersectionObserver) | 의존성 최소 | 줄 단위 마스크 등장, 스크롤 연동 같은 효과를 직접 만들면 코드가 늘고 완성도가 떨어져 버림 |

스크롤

| 안 | 결과 |
| --- | --- |
| **Lenis** | **채택.** 네이티브 스크롤 위치를 보간하므로 sticky, 앵커, 고정 네비게이션이 그대로 동작한다. 약 3KB |
| GSAP ScrollSmoother | 의존성은 하나로 끝나지만 콘텐츠를 래퍼로 감싸 `transform`으로 움직여서 고정 요소·앵커·Next 페이지 전환에서 손볼 곳이 많다. 버림 |
| CSS `scroll-behavior`만 | 관성감이 없어 요구에 못 미친다 |

디더링 질감

| 안 | 결과 |
| --- | --- |
| **셰이더 안에서 베이어 행렬 디더링** | **채택.** 색 필드를 양자화하는 몇 줄이라 배경 셰이더(D-018)와 한 번에 처리된다 |
| CSS 패턴 오버레이 | 가볍지만 그라데이션 밝기와 연동되지 않아 #6처럼 번지지 않는다. WebGL 폴백에서만 근사로 쓴다 |

## 결정

**시각 언어**
- 바탕은 검정(`--paper`). 색은 주황, 파랑, 마젠타 계열의 큰 곡선 하나가 천천히 휘감기고, 색 점이 섞인 그레인을 얹는다. 청록 단색은 버린다(D-018 팔레트 대체, 구체 값은 계획에서 확정).
- 셰이더(D-018 2단계)가 이 배경을 담당한다: 노이즈로 곡선 흐름 + 베이어 디더링 + 밝기 가중 색 점 그레인 + 스크롤 progress uniform. CSS 폴백은 유지한다.
- 글래스는 D-018 C 값(blur 7px, 굴절 scale 70, 어두운 베이스)을 유지하고 **네비게이션과 카드 한두 개에만** 쓴다. 굴절은 뒤에 구조가 있어야 보이므로(Task 3 검증 결과) 큰 글자·선·빛의 경계가 유리 뒤를 지나가게 배치한다.

**레이아웃**
- 화면을 꽉 채우는 풀폭 섹션. 제목은 크게(화면 폭 기준 9vw 안팎, 얇은 굵기), 문장은 짧게, 여백은 넉넉하게.
- 메인 첫 화면: 글래스 알약 네비게이션(+ 흰 알약 CTA), 중앙의 거대한 한 줄 제목과 한 문장 설명, 버튼 하나, 스크롤 표시.
- 상세 페이지: 좌측 목차와 박스 중첩을 없앤다. 풀폭 띠마다 큰 번호와 큰 제목, 숫자는 큰 픽셀·모노 서체로, #6처럼 어두운 카드를 선택적으로 쓴다.
- 읽는 면(`.panel`)은 유지하되 본문 단락에만 쓴다(가독성 규칙은 그대로, D-011).

**모션** (Lenis + GSAP)
- Lenis: 스무스 스크롤. GSAP 티커에 `lenis.raf`를 연결하고 `lenis.on('scroll', ScrollTrigger.update)`, `gsap.ticker.lagSmoothing(0)`을 설정하는 공식 패턴을 따른다.
- GSAP: ScrollTrigger, SplitText. 제목 줄 단위 마스크 등장, 스크롤 연동 패럴랙스, 배경 셰이더의 스크롤 연동, 숫자 카운트업, 네비게이션 숨김·표시, 글래스 버튼 호버.
- React에서는 `@gsap/react`의 `useGSAP`으로 정리(cleanup)한다. 애니메이션 코드는 클라이언트 컴포넌트에만 둔다.
- `prefers-reduced-motion`이면 Lenis와 GSAP 연출을 끄고 정적 상태로 보인다.
- 제목은 **항상 실제 DOM 텍스트**로 두고 SplitText는 마운트 후에 분할한다(JS가 없어도 읽히고 검색 노출에 지장이 없게).

**서체** (제안, 계획에서 확정)
- 영문 제목은 Geist 얇은 굵기. 한글은 Pretendard 계열로 교체를 제안한다(Noto Sans KR의 공문서 인상 완화). 숫자용 픽셀·모노 서체는 후보를 계획에서 고른다.

**작업 순서**
1. 셰이더 배경(디더링 + 색 점 그레인 + CSS 폴백, 새 팔레트)
2. 모션 기반(Lenis + GSAP 설정, 훅)
3. 메인 첫 화면
4. 상세 페이지 리디자인
5. 문서 정리와 전체 검증

## 이유

- 사용자가 원하는 것은 "시원시원하고 해외 스타일"이다. 요소를 덜어내고(큰 제목, 큰 여백) 움직임을 늘리는 방향이 레퍼런스와 맞다.
- #6의 디더링은 셰이더로 자연스럽게 해결되어 D-018의 셰이더 결정을 강화한다.
- GSAP + Lenis는 해외 어워드급 사이트에서 가장 흔한 조합이라 자료가 많고, 이 프로젝트가 스크롤 연출 중심이라 맞는다.

## 알고 있는 단점 / 비용

- 의존성이 `lenis`, `gsap`, `@gsap/react` 세 개 늘어난다(D-018 계획의 "새 의존성 없음" 제약은 이 결정으로 갱신).
- 셰이더, 스무스 스크롤, 굴절 글래스를 함께 쓰면 모바일 성능이 위험하다. Lenis + GSAP + WebGL이 모바일에서 느려진다는 이슈 보고가 있다. 모바일에서는 셰이더 해상도, 글래스 수, 연출 수를 줄이고, 측정(FPS, LCP)해서 기록한다.
- GSAP는 번들이 크다(코어 + ScrollTrigger + SplitText). 필요한 플러그인만 가져오고 클라이언트 경계를 작게 둔다.
- GSAP 라이선스: 현재 npm `gsap` 패키지의 플러그인(SplitText, ScrollSmoother 포함)이 상업적 사용까지 무료이고 Webflow가 표준 라이선스로 공개했다. 다만 약관은 바뀔 수 있고 금지 사용 조항이 있어서 도입 시점에 전문을 확인한다.
- 굴절 `backdrop-filter`는 Chromium 계열에서만 동작한다(D-018). Safari·Firefox는 직접 확인하지 못했다.
- 새 배경에서 글자 대비를 다시 측정해야 한다. 이전에 확인된 위험: 바탕 위의 작은 `--ink-3`·`--ink-2` 글자는 밝은 빛 위에서 4.5:1을 못 지킨다(vivid 측정 2.25~4.36). **큰 제목은 밝은 곡선 위에 얹어도 되지만 작은 글자는 어두운 영역·패널·글래스 위에만 둔다.** 모바일 PROJECT 칩 대비는 기준과 0.29 차이다.

## 면접 포인트

- "왜 GSAP와 Motion 중 GSAP를 골랐나?" → 스크롤 연동·고정·글자 분할이 핵심이어서 ScrollTrigger와 SplitText가 있는 GSAP가 맞았고, 상태 전환 중심이면 Motion이 낫다.
- "왜 ScrollSmoother가 아니라 Lenis인가?" → ScrollSmoother는 콘텐츠를 래퍼로 `transform`하므로 sticky·앵커·페이지 전환에서 충돌이 생긴다. Lenis는 네이티브 스크롤을 유지한다.
- "무거운 효과의 성능과 접근성을 어떻게 지켰나?" → 모바일 축소, reduced-motion에서 전부 정지, 실제 DOM 텍스트, 대비 실측. 측정값은 구현 후 기록한다(측정 전).

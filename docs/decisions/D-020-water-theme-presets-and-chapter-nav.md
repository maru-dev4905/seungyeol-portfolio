# D-020 시안 기준 팔레트, 페이지·프로젝트별 테마 프리셋, 생성형 커버, 글래스 알약 목차

- 상태: 일부 미정 (테마 프리셋의 정확한 색 값, 소개 페이지 이끼 팔레트는 만들면서 확정)
- 날짜: 2026-11-18

> D-019의 팔레트(주황, 마젠타)를 **깊은 네이비 → 블루 → 시안 → 흰 빛** 구조로 바꾼다(레퍼런스 #9, #10).
> 색은 **테마 프리셋**으로 만들어 페이지마다, 프로젝트마다 다르게 쓰고, 이미지가 없을 때는 **생성형 그라데이션 커버**를 쓴다.
> 상세 페이지의 "On this page"는 정적 좌측 목차 대신 **화면 아래 글래스 알약**으로 바꾼다.

## 배경

D-019 구현(셰이더 배경)을 본 사용자의 피드백:
- 색을 #9("Rise"), #10("Surface") 같은 **파랑 계열**로 바꾸고, 서브 페이지마다 색이 조금씩 다르면 좋겠다. 포트폴리오는 나를 소개하는 것이므로 **좋아하는 것(파랑, 이끼 초록)** 에서 대표 색을 가져오고 싶다.
- 프로젝트마다 대표 색이 있으니 **그 색에 따라 배경이 달라지게** 할 수 있는지.
- 레이아웃이 아쉽다: 간격이 더 시원해야 하고, 스크롤이 심심하지 않아야 하고, **이미지가 없을 때**의 처리를 정해야 하고, "On this page"가 다른 사이트처럼 왼쪽에 정적으로 있다.

## 결정

**색 (시안 기준)**
- 대표색: "새벽 물빛 시안"(`#4fd1c5` 근처). 파랑과 이끼 초록 사이의 색이고, 물, 어둠 끝에서 빛이 터지는 전환의 순간을 뜻한다(설계자의 제안, 사용자가 시안 기준 수락).
- 토큰 이름을 의미 이름(ember, magenta…)에서 **램프 위치**로 바꾼다: `--ramp-0`(가장 어두움) … `--ramp-4`(가장 밝은 빛) + `--accent`. 셰이더가 읽는 순서와 같다.
- 테마 프리셋은 `[data-theme="..."]` 선택자 아래에 같은 토큰을 다시 정의한다. 요소 하나에 `data-theme`를 붙이면 그 요소 안에서만 색이 바뀐다(커버 카드가 이 방식을 쓴다).
- 초기 프리셋(값은 제안): `water`(네이비 → 로열 블루 → 시안 → 흰 빛, 메인), `moss`(짙은 이끼 → 이끼 → 연한 라임·시안 빛, 소개), `dusk`(네이비 → 바이올렛 → 마젠타 → 주황, 지금의 따뜻한 계열을 프로젝트용으로 보존).

**테마 적용**
- 메인은 `water`, 소개는 `moss`, 프로젝트 상세는 `project.theme`.
- `Backdrop`을 페이지가 아니라 **레이아웃에 한 번** 둔다. 테마가 바뀌면 팔레트 uniform을 **약 1초 동안 보간**해서 색이 섞이며 바뀐다(D-019 검증에서 확인한 "팔레트는 마운트 시 한 번만 읽는다" 제약 해소, WebGL 컨텍스트 반복 생성도 사라진다).
- 페이지는 `<ThemeSetter theme="..." />`(클라이언트, null 렌더)로 현재 테마를 알린다. 테마 값은 우선 샘플 데이터(`ProjectDetail.theme`)에 두고, DB 단계에서 `THEME` 공통 코드로 옮긴다(D-002).

**레이아웃과 스크롤**
- 간격: 챕터 사이를 1~1.5화면 높이로 벌리고, 제목은 더 크게, 본문 폭은 좁게.
- 스크롤 연출(후보 중 채택): ① 작업 목록에서 큰 번호가 고정(pin)되고 프로젝트가 지나가며 번호와 배경 테마가 바뀜, ② 상세 섹션을 챕터처럼 한 장씩(큰 번호, 줄별 등장, 숫자 카운트업), ③ 스크롤에 따라 배경 곡선이 흐르고 챕터마다 테마색이 조금씩 이동. 단어별로 밝아지는 문장 연출은 소개 페이지에서 따로 쓴다.
- 읽는 글자는 계속 어두운 영역·패널·글래스 위에 둔다(D-019 검증: calm 밝기를 올리면 작은 글자 대비가 깨짐). 시원한 간격으로 생기는 빈 구간에 곡선이 지나가게 한다.

**커버**: `GradientCover`(프로젝트 테마색 + 제목 얹기). 프로젝트 카드, 상세 히어로, 갤러리 자리에 쓴다.

**On this page**: `ChapterNav`(글래스 알약, ScrollTrigger로 현재 챕터 감지, 키보드·스크린리더 지원).

**모양 프리셋 (일렁이는 곡선의 형태·크기)**
- 색만 바뀌고 곡선 모양이 모든 페이지에서 같으면 같은 배경으로 보인다는 지적에 따라, 곡선의 **모양도 프리셋**으로 만든다. 모양은 위치, 크기, 띠 폭, 휘어짐, 회전 같은 몇 개의 숫자(uniform)로 정의하고, 테마 색과 똑같이 페이지를 옮길 때 약 1초 동안 **보간**해서 모양이 흘러 변한다.
- 초기 프리셋(레퍼런스에서 읽은 구도): `rise`(화면 가운데에 큰 어두운 공간, 위쪽을 따라 블루 빛 띠, 오른쪽 가장자리에 흰 빛이 터짐, #9), `surface`(오른쪽 위 모서리의 거대한 흰 빛이 블루로 번져 내려오고 아래에 어두운 반달, #10), `ribbon`(화면을 가로지르는 S자 곡선, #8), `halo`(화면의 반쯤을 차지하는 크고 둥근 빛, Blur Light). 크기는 이전보다 **과감하게** 키운다.
- **적용 방식: 안 C(사용자 선택).** 페이지마다 기본 모양을 정하고, 방문마다 위치·위상·회전·크기를 **조금씩 무작위로 흔든다**(jitter). 프로젝트 상세는 챕터가 바뀔 때 모양이 서서히 이동한다. 기본 배정(제안): **메인 `rise`(사용자 지정)**, 소개 `halo`, 프로젝트 상세 `surface`에서 시작해 챕터마다 `ribbon`, `rise`로 순환.
- 선택지: A(페이지마다 고정)는 일관되지만 단조롭고, B(방문마다 프리셋 무작위)는 재미있지만 브랜드 일관성이 약해지고 대비 검증이 어렵다. C는 같은 사이트로 느껴지면서 매번 다른 표정이 난다.
- 제약: 빛 면적이 커질수록 작은 글자 뒤가 밝아져 대비가 깨진다(D-019 검증: calm 밝기를 올리면 4.5:1 미달). 그래서 모양마다 글자가 올라가는 영역은 어둡게 남기거나 패널·글래스로 받치는 구도여야 하고, **모양 × 테마 × jitter 극단값 조합을 전부 실측**한다. 셰이더의 밝기 gain은 올리지 않는다.

## 이유

- 팔레트가 토큰과 셰이더 uniform으로 되어 있어서 색 교체와 페이지별 테마 전환 비용이 작다.
- 프리셋은 일관성을 지키면서도 "프로젝트마다 다른 색"을 만족한다.
- 알약은 정적 좌측 목차가 JS 없이는 못 하던 "현재 위치 표시"를 ScrollTrigger로 해결하고 굴절 글래스의 쓰임새를 만든다.

## 알고 있는 단점 / 비용

- SSR 첫 페인트는 기본 테마(`water`)이고, 하이드레이션 뒤에 해당 페이지 테마로 보간된다. 프로젝트 페이지에서 첫 순간 색이 바뀌는 깜빡임이 있을 수 있다(측정 후 필요하면 보완).
- 프리셋 수가 제한된다. 새 색이 필요하면 프리셋을 추가해야 한다.
- 알약은 화면 아래에 고정되므로 모바일의 하단 UI(주소창, 홈 인디케이터)와 겹칠 수 있다(`safe-area-inset-bottom` 고려). 굴절은 Chromium 계열에서만 동작한다(D-018).
- 램프 위치 이름으로 바꾸면 기존 `--paint-*` 사용처를 모두 수정해야 한다.

## 면접 포인트

- "테마를 어떻게 구현했나?" → CSS 커스텀 프로퍼티를 `[data-theme]`로 스코프하고, WebGL 셰이더가 같은 토큰을 읽어 uniform으로 보간한다. 색의 출처가 한 곳이다.
- "배경을 레이아웃에 올린 이유?" → 페이지 이동 시 캔버스를 새로 만들지 않아 컨텍스트 낭비가 없고, 색을 부드럽게 전환할 수 있다.
- "이미지가 없을 때의 UX?" → 테마색 생성형 커버로 빈 상태를 디자인의 일부로 만들었다.

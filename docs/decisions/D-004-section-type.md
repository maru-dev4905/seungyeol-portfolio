# D-004 섹션 type은 문자열 + CHECK

- 상태: 확정
- 날짜: 2026-11-17

> 섹션 `type`은 공통 코드로 빼지 않고, 문자열 컬럼에 CHECK 제약을 건다.

## 배경

스펙·카테고리를 공통 코드로 두었으니(D-002), 섹션 타입도 공통 코드로 둘 수 있었다.

## 고민한 선택지

| 안 | 방식 | 결과 |
| --- | --- | --- |
| A | 공통 코드(`SECTION` 그룹) | 값 추가는 쉬워 보이지만 아래 이유로 이점이 없음 |
| B | 문자열 + CHECK | **채택** |

## 결정

```sql
type text CHECK (type IN ('markdown', 'troubleshooting', 'metrics', 'gallery', 'video'))
```

## 이유

섹션 타입을 하나 추가하려면 **어차피 그 타입을 그릴 React 컴포넌트와 zod 스키마를 새로 만들어야** 한다.
공통 코드로 빼도 "코드 수정 없이 추가"라는 장점이 생기지 않는다.

## 면접 포인트

같은 "분류값"이라도 **화면 코드와 묶여 있는지**에 따라 저장 방식을 다르게 골랐다.
SPEC·CATE는 화면 코드와 묶여 있지 않고(값만 늘면 됨), 섹션 `type`은 묶여 있다(컴포넌트가 필요함).

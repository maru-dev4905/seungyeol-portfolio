# D-018 어두운 바탕 + WebGL 그레인 셰이더 배경 + SVG 굴절 글래스

- 상태: 일부 미정 (팔레트·작업 순서는 D-019가 대체. 굴절 글래스 C 값은 유지: blur 7px, scale 70, 어두운 베이스 `rgba(8,14,18,0.35)`)
- 날짜: 2026-11-18

> 바탕을 밝은 파스텔에서 **어두운 바탕에 빛이 번지는 모습**으로 바꾼다.
> 배경은 WebGL 셰이더(밝기 가중 그레인 + 약한 색수차), UI 유리는 SVG 굴절(`feDisplacementMap`)로 만들고, 둘 다 CSS 폴백을 둔다.
> D-011의 컨셉은 유지하고, D-017의 "밝은 파스텔" 해석만 대체한다.

## 배경

레퍼런스 이미지(Blur Light 그레인 배경, 리퀴드글래스 UI, 해외 그레이니 그라데이션 사이트)를 가져와서 방향을 다시 잡았다.
D-017 샘플은 밝은 종이색 + 파스텔 + 블러 유리라서 레퍼런스와 결이 달랐다.

- 배경: 어두운 바탕, 청록·주황 계열의 번진 빛, **밝기에 따라 세기가 다른 필름 그레인**, 가장자리의 무지개 번짐(색수차).
- 유리: 블러가 아니라 **굴절**. 가장자리에서 뒤 배경이 휘어 보이고 테두리에 빛이 맺힌다.
- 타이포: 자간이 넓은 대문자 라벨 + 큰 흰 글자 + 작은 보조 문구.

## 고민한 선택지

배경

| 안 | 방식 | 결과 |
| --- | --- | --- |
| A. CSS 그라데이션 유지 | 색만 어둡게 | 번진 빛은 되지만 그레인이 모든 곳에 같은 세기로 깔리고 움직이지 않는다. 색수차는 사실상 불가. 폴백으로 남긴다 |
| B. 이미지 한 장을 구워서 사용 | 외형 정확, 코드 거의 없음 | 그레인 이미지는 압축이 안 돼 용량이 크고, 움직임이 없고, 코드로 만든 FE 대표작이라는 의미가 약해서 버림 |
| C. WebGL 셰이더 + CSS 폴백 | 프래그먼트 셰이더 하나로 빛, 그레인, 색수차 | **채택** |

유리

| 안 | 방식 | 결과 |
| --- | --- | --- |
| A. 블러 + 테두리 빛 | 서리 유리 | 모든 브라우저 동일하지만 굴절이 없다. 폴백으로 남긴다 |
| B. A + SVG 굴절 (점진적 향상) | `backdrop-filter: url(#필터)` | **채택** |
| C. 유리도 WebGL로 그리기 | 가장 자유롭다 | DOM 텍스트·접근성과 어긋나고 비용이 크다. 버림 |

## 결정

- **토큰**: `globals.css`를 어두운 팔레트(near-black 바탕, 흰 글자, 청록 중심의 빛 색)로 교체한다. 컴포넌트는 `var(--...)`만 쓴다는 D-016 규칙은 그대로.
- **`Backdrop`**: 겉모습(`intensity="vivid" | "calm"`)은 유지하고 안쪽을 교체한다.
  - 기본: 순수 WebGL(라이브러리 없음), 화면 전체 삼각형 + 프래그먼트 셰이더 하나.
  - 폴백: 지금의 CSS 그라데이션 + 그레인(어두운 색으로 변경). WebGL 불가, 로딩 중, 저사양일 때.
  - 서버 컴포넌트 셸 안에 캔버스 클라이언트 컴포넌트만 작게 둔다.
- **셰이더**: 노이즈로 빛 덩어리를 흐르게 하고, 그레인은 밝기에 비례해 세게, 색수차는 밝은 영역의 가장자리에 약하게.
- **성능**: 절반 해상도로 그리기, 30fps 제한, 탭이 숨겨지거나 화면 밖이면 정지, `prefers-reduced-motion`이면 한 프레임만, 모바일은 해상도·효과 축소.
- **`.glass`**: 블러 + 얇은 안쪽 테두리 빛 + SVG 굴절 필터. Chromium에서는 굴절, 그 외 브라우저는 블러+테두리로 자동 폴백(`@supports`). `.panel`(읽는 면)은 어둡게 불투명도 높여서 유지.
- **글자 대비**: 어두운 바탕이라 흰 글자 대비 확보가 쉽다. 유리 위 글자는 대비를 직접 측정한다.

## 이유

- 굴절 유리는 뒤의 빛이 살아 있어야 티가 난다. 그래서 배경과 유리는 경쟁이 아니라 한 쌍이다.
- 그레인의 밝기 가중과 색수차는 CSS로 낼 수 없는 부분이라 셰이더가 필요하다.
- `Backdrop`의 인터페이스가 그대로라서 셰이더가 어려우면 CSS 폴백으로 먼저 가도 나머지가 막히지 않는다.
- 순수 WebGL은 코드가 100줄 안팎이라 한 줄씩 설명할 수 있다.

## 알고 있는 단점 / 비용

- SVG 굴절 `backdrop-filter`는 현재 Chromium 계열에서만 동작한다. Safari·Firefox에서는 굴절 없이 블러로 보인다.
- 캔버스 위의 `backdrop-filter` 굴절은 GPU 비용이 있다. 글래스 요소는 화면당 소수로 제한한다(D-011).
- GLSL을 새로 배워야 한다.
- D-017이 "덜어내는 방향"으로 해석했던 파스텔·저채도 원칙은 바뀐다. 어두운 바탕에서도 "색은 적게, 움직임은 배경에만, 느리게"는 유지한다.

## 면접 포인트

- "무거운 시각 효과에서 성능과 접근성을 어떻게 지켰나?" → 절반 해상도, 30fps 제한, 비가시 시 정지, reduced-motion 정적 프레임, CSS 폴백. FPS·LCP 측정값을 남긴다(측정 후 기록).
- "왜 WebGL이었나, CSS로는 안 되나?" → 밝기 가중 그레인과 색수차는 CSS로 불가. 그래서 배경만 셰이더로, UI는 DOM 그대로(접근성).
- "브라우저 호환은?" → 점진적 향상. 기능이 없어도 읽을 수 있는 폴백.

# D-016 스타일링은 CSS Modules + 전역 디자인 토큰으로

- 상태: 잠정 확정 (샘플을 만들며 정한 기본값. 이견이 있으면 바꾼다)
- 날짜: 2026-11-17

> 값(색·글꼴·반경)은 `globals.css`의 CSS 변수(토큰) 한 곳에, 컴포넌트 스타일은 CSS Modules에 둔다. Tailwind는 쓰지 않는다.

## 배경

`create-next-app`을 `--no-tailwind`로 만들었고, 상세 페이지 샘플을 만들면서 스타일링 방식을 정해야 했다.
이 사이트의 핵심 스타일(그레인 배경, 리퀴드 글래스, 애니메이션)은 `backdrop-filter`, `mix-blend-mode`, `@keyframes` 같은 **순수 CSS를 직접 다루는 일**이 대부분이다.

## 고민한 선택지

| 안 | 장점 | 단점 |
| --- | --- | --- |
| **A. CSS Modules + CSS 변수** | 런타임 비용이 없다. 클래스 이름이 컴포넌트별로 격리된다. 서버 컴포넌트에서 그대로 동작한다. 순수 CSS라 설명하기 쉽다 | 공통 스타일을 직접 관리해야 한다 |
| B. Tailwind | 빠르게 만들 수 있다 | 글래스·그레인처럼 긴 CSS가 className에 길게 늘어난다. 지금 없는 도구를 추가하는 비용 |
| C. CSS-in-JS | 동적 스타일이 쉽다 | 런타임 비용, 서버 컴포넌트와 궁합이 나쁘다 |

## 결정

- **토큰**: `--paper`, `--ink`, `--accent`, `--paint-*`, `--radius-*`, `--font-*` 등을 `:root`에 둔다. 컴포넌트는 값을 직접 쓰지 않고 `var(--...)`만 쓴다.
- **공용 표면 2종**: `.glass`(블러가 있는 유리), `.panel`(블러 없이 불투명한 읽는 면)을 `globals.css`의 전역 클래스로 둔다.
- **컴포넌트 스타일**: 컴포넌트와 같은 폴더의 `*.module.css`.

## 이유

- 가장 많이 쓰는 기술이 CSS 자체이고, 이 사이트는 "코드 전부를 설명할 수 있어야" 한다. 도구가 적을수록 설명할 것이 줄어든다.
- 토큰이 한 곳에 있으면 메인의 색 팔레트(D-011 남은 질문)가 정해졌을 때 한 파일만 고치면 된다.

## 면접 포인트

"스타일링을 왜 이렇게 했나요?" → 효과(블러, 블렌드, 키프레임) 중심의 디자인이라 순수 CSS가 가장 직접적이었고, 런타임 비용이 없는 CSS Modules를 골랐다. 값은 토큰으로 모아 한 곳에서 바꾼다.
